# Prime Visuals 2.0 — локальные настройки и конфиги

## Автосохранение

Сохраняются 178 зарегистрированных параметров: переключатели, числа, выбранные варианты, текстовые поля, цвета, поднастройки, радуга и ручной цвет под ней. Сохраняются выбранные игроки ESP, в том числе временно отсутствующие на сервере. Для неба записываются введённый ID/ссылка и разрешённые свойства Sky, включая все шесть текстур: при восстановлении не нужен повторный запрос модели. Положение окна, последняя вкладка и расположение панелей настроек тоже сохраняются.

Изменения объединяются в запись с задержкой 0,4 секунды; анимации цветов не создают записи. При полном закрытии скрипта есть дополнительная синхронная запись. Обработчик выхода локального игрока также пытается сохранить состояние. При ошибке записи выполняются повторные попытки с увеличением задержки до 30 секунд. Принудительное завершение процесса до первой записи может потерять последние доли секунды изменений.

Данные находятся на устройстве в рабочей папке executor. Корень для конкретного Roblox-аккаунта:

```text
PrimeVisuals/Configs/<Roblox UserId>/
  autosave.json
  autosave.backup.json
  slots/
    slot1.json
    slot1.backup.json
    ... slot2–slot5 ...
  exports/
    slot1.json
```

Это относительный путь. В Settings есть кнопка его копирования. Полный путь зависит от executor и его установки; универсального открытия проводника через Roblox нет. При отсутствии `readfile`, `writefile`, `isfolder`, `makefolder` меню продолжит работать и явно покажет, что автосохранение недоступно.

Исходные настройки игры остаются исходными: пока FOV, время или солнце не менялись вручную, следующий запуск использует обычные значения текущей игры. Полный сброс заменяет автосохранение чистыми настройками, сохраняя именованные слоты. Полная выгрузка возвращает игру к исходному состоянию, но сохраняет пользовательские настройки для следующего запуска.

Сохраняются настройки, а не записи действий. Кнопки спавна/удаления манекенов, захват предметов, здоровье и серверные события автоматически не воспроизводятся. Имя аватара, физика и остальные параметры манекенов сохраняются.

## Пять слотов

1. Настрой оформление и открой Settings → Configurations.
2. Выбери слот 1–5, впиши название и нажми Save to slot.
3. Load slot загружает настройки из выбранного слота. Сводка под полем названия показывает число отличающихся параметров; изменение данных неба учитывается отдельно.
4. Undo last config load возвращает состояние до последней загрузки. Это одна отмена в текущем запуске скрипта, без истории после перезапуска Roblox.
5. Для перезаписи занятого слота повтори ту же кнопку в течение 6 секунд. Подтверждение содержит прежнее название. Смена операции или слота не переносит подтверждение. Удаление также требует второго нажатия.

Загрузка перестраивает интерфейс с полной очисткой прежних эффектов, затем выставляет параметры и включает функции. Данные скайбокса восстанавливаются раньше сохранённых параметров солнца и облаков. Автосохранение после загрузки становится текущим выбранным оформлением; именованный слот от этого не меняется.

## Обмен

- Export selected slot записывает переносимый JSON в `exports/slotN.json` и при доступном clipboard копирует путь.
- Другу нужно положить этот файл в `PrimeVisuals/Imports/`, например `friend.json`.
- В Settings выбрать целевой слот, ввести только имя файла и нажать Import into selected slot. Для занятого слота требуется подтверждение.
- После импорта нажать Load slot. Конфиги другого UserId разрешены, а автоматические настройки разных аккаунтов хранятся отдельно.

JSON — только данные, он не запускается как Lua. Перед заменой слота проверяются формат, схема, типы параметров, диапазоны, цвета, перечисления, текстуры неба и координаты. Размер файла ограничен 512 КиБ; обход папки через путь в имени импорта запрещён. Неизвестные ключи параметров игнорируются для совместимости, известные некорректные значения отклоняются.

## Запись и восстановление

Каждая запись содержит схему 1, версию скрипта и номер ревизии. Сначала записывается более старая сторона двухфайлового журнала, затем проверяется чтением, затем обновляется вторая сторона. При чтении выбирается самая новая корректная ревизия. Это сохраняет одну пригодную копию при обрыве одной записи; это не бессрочная история версий и не защита от потери обеих копий на диске.

Удаление записывает пустую отметку удаления в обе стороны журнала, чтобы резервная копия не вернула удалённый слот. При повреждении обеих автоматических копий скрипт запускается без восстановления и не затирает повреждённые данные только из-за открытия/закрытия меню. Явное изменение настройки или полный сброс начинает новое автосохранение.
